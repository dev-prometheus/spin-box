# Visual direction and design system

## Goal

Create a distinctive, product-led interface with clear money presentation and high-quality composition. The existing narrow dark/orange card stack is rejected. Neither its palette nor layout is mandatory.

## Explore before choosing

Prepare three genuinely different directions. Vary composition, density, typography and personality as well as palette. Show the same realistic landing hero and signed-in product/stake view at full readable size on mobile and desktop. Label all example amounts as demonstration data. Explain each direction's benefit and cost. Do not offer three accent swaps of the same layout.

Keep variants isolated from production. When a direction is chosen, record its semantic tokens and component examples here; do not silently choose a final palette before user selection.

## Avoid template habits

Do not default to purple/blue gradients, ambient neon glows, ornamental glass, floating abstract blobs, tiny uppercase eyebrow labels everywhere, repeated badge rows or a rounded card around every paragraph. No hue is intrinsically AI-generated; evaluate its role, execution and brand fit. Do not impose glass materials from Apple references where they conflict with this project's solid-surface preference.

Use deliberate whitespace, product imagery, clear grouping and distinctive type proportions. Restrict strong accents to meaningful actions/states. Separate brand accent from success, loss, retry and warning semantics. Do not show every metric in green. Avoid aggressive loss styling or visual pressure to wager again.

## Token checklist

Define canvas, surface, elevated surface, border, primary/muted text, brand/action, success, danger, warning, focus and disabled colors. Define hover/pressed/selected states and text-on-accent pairs. Check contrast for each actual pairing; target at least 4.5:1 for normal text, 3:1 for large text and relevant UI boundaries. Never rely on color alone.

Define type families/fallbacks, display and body scales, numeric styling, spacing scale, content widths, radii, control heights and motion tokens. Use readable default body sizing, approximately 16px with comfortable line height; dense data can be smaller if still legible. Avoid global heavy weights and overly tight body tracking. Use tabular numerals for aligned financial data.

Build examples for buttons, labeled fields, currency amounts, product preview, stake ticket, tabs, transaction rows, alerts, skeletons and dialogs. Specify normal/focus/hover/pressed/loading/disabled/error states. Use a consistent icon family and visible labels where meaning is unclear.

## Definition of done

Provide chosen tokens, desktop/mobile compositions, component states and contrast evidence. Check image cropping, long product names, large balances and empty states. A visually impressive hero alone is not a finished design system.
